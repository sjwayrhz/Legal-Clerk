# 执行材料PDF 批量拆分工具
## 1、程序概述
本Python工具面向强制执行案件材料整理工作，可自动检索当前目录以及一级子目录内【强制执行申请材料.pdf】总合档文件，根据预设页码拆分分离出各类独立文书PDF；每处理完一处案件文件夹后，自动创建Windows文件夹快捷方式，快速跳转至备用素材目录，实现案件材料一键拆分、简化日常卷宗整理流程。

## 2、运行环境
### 2.1 操作系统
仅支持 Windows 系统，创建lnk快捷方式依赖Windows‑COM接口，Linux、MacOS无法运行快捷方式生成功能。
### 2.2 依赖组件
安装命令，于CMD执行：
```bash
pip install PyPDF2 pywin32
```
- PyPDF2：负责PDF文档读取、页面截取、拆分输出独立文书
- pywin32：调用Windows系统接口，生成 .lnk 文件夹快捷方式

## 3、目录结构规范
### 3.1 文件命名要求
整套合并后的卷宗PDF**固定命名：强制执行申请材料.pdf**
### 3.2 文件夹结构示例
```
案件根目录
├─ 001号案件（子文件夹）
│   └─ 强制执行申请材料.pdf
├─ 002号案件（子文件夹）
│   └─ 强制执行申请材料.pdf
└─ split_pdf.py（本工具脚本）
```
> 脚本会同时检索根目录、全部一级子文件夹当中的目标PDF文件，深层嵌套二级文件夹不会扫描。

## 4、拆分输出清单（固定截取页码下标）
> 注意：PyPDF2页码下标从0开始计数，文档第一页对应下标0
|拆分后文件名称|截取PDF下标页码|文书用途|
| ---- | ---- | ---- |
|强制执行申请书.pdf|5|案件主申请书|
|被执行人身份证.pdf|14|被执行人身份证件扫描件|
|授权委托书.pdf|13|代理授权文书|
|送达地址确认书.pdf|11|文书送达确认表单|
|银行账户确认书.pdf|10|被执行人财产账户材料|
|纳入失信申请书.pdf|9|失信被执行人申请文书|
|限高申请书.pdf|8|限制高消费申请书|

1. 如果源PDF总页数小于需要读取的页码，程序自动跳过该文书并弹出警告，不会报错终止任务；
2. 所有拆分完毕的独立PDF，输出至源PDF所在的案件文件夹内。

## 5、快捷方式生成规则
每成功处理一份PDF之后，会在该案件PDF所在目录自动生成2个Windows快捷方式：
1. `申请人身份材料.lnk`：跳转路径 `D:\sync\申请人身份材料`
2. `授权委托书.lnk`：跳转路径 `D:\sync\授权委托书`

作用：卷宗整理的时候，可以通过快捷入口快速调取通用模板、当事人身份备用资料。
当目标文件夹不存在，程序会跳过当前快捷方式创建并输出提示日志。

## 6、操作步骤
1. 将脚本放置在案件根目录；
2. 确认所有合并卷宗PDF命名为 `强制执行申请材料.pdf`；
3. CMD切换至当前工作目录，执行脚本；
4. 程序自动扫描目录、批量拆分文书、生成文件夹快捷方式；
5. 查看控制台日志，确认成功项、跳过项、异常报错信息；
6. 单个PDF读取失败不会中断整体批量任务，其余卷宗正常处理。

## 7、重要注意事项
1. 合并版PDF页面顺序不可改动，一旦页面顺序调换，拆分出来的文书内容就会出错；页面发生变动时，需要修改脚本内 `page_mapping` 页码对照表；
2. 仅能够识别一级子文件夹，不会遍历第二层及更深文件夹；
3. 快捷方式功能仅限Windows系统可用；
4. 仅支持标准文本PDF；加密、受权限限制、图片扫描版PDF会读取失败；
5. 所有输出文件会直接存放在源PDF同级目录，不会新建输出文件夹。

## 8、故障排查
1. 无法创建快捷方式：检查 `D:\sync\申请人身份材料`、`D:\sync\授权委托书` 两个文件夹真实存在；
2. 拆分出来PDF内容错乱：检查合并文档页码顺序，更新脚本页码映射；
3. 找不到目标PDF：核对文件全名，不能出现多余空格、文字改动；
4. 提示依赖缺失，重新执行pip安装命令。

## 9、拓展说明
本程序可以和【强制执行申请书PDF批量信息提取工具】搭配使用，拆分完强制执行申请书PDF之后，再运行信息提取脚本批量抓取被执行人信息，组成完整案件材料处理流水线。



# 批量替换PDF中的字符
## 1、程序概述
本工具基于PyMuPDF‑fitz开发，用来**批量递归检索当前目录以及全部深层子文件夹内所有PDF文档**，对指定姓名、身份证号码、联系电话等文本内容进行精准替换。
工具具备高级字体适配功能：自动读取PDF内嵌字体、校验字体是否包含目标替换文字的字形，替换之后沿用原有文字的字体、字号、文字颜色、坐标位置；先遮盖原有旧文字，再写入新文本，实现无痕修改PDF，适配强制执行申请书批量修改当事人信息的业务场景。

## 2、运行环境
### 2.1 操作系统
Windows、Linux、MacOS全平台均可运行
### 2.2 依赖安装
CMD / 终端执行安装PyMuPDF库
```bash
pip install pymupdf
```

## 3、核心参数配置说明
所有待替换内容在脚本顶部`REPLACEMENTS`列表配置，格式为`(旧文本,新文本)`
```python
REPLACEMENTS = [
    ("顾小翔", "周晓林"),
    ("372328197010050096", "370784198402038219"),
    ("17638192436", "18913125617"),
]
```
> 使用方法：按需增删数组，填入需要批量更换的当事人姓名、手机号、身份证号、住址等内容

## 4、完整工作原理
### 4.1 全局扫描PDF
脚本启动之后，递归扫描脚本所在根目录、所有层级子文件夹，检索后缀为`.pdf`、`.PDF`的全部文件，自动去重、排序文件列表。

### 4.2 单页文字与内嵌字体解析
1. 读取PDF每一页，拆解页面所有文字块、文字片段span，记录每一处文字的坐标、字号、RGB颜色、字体名称；
2. 提取页面内部所有嵌入字体，导出至系统临时文件；

### 4.3 字体可用性校验（本工具核心特色）
很多PDF的中文字体属于字体子集，字体编码存在但是缺少对应汉字轮廓，直接替换文字会出现空白方块。
工具会逐个字符进行像素渲染测试：
> 在空白画布渲染单个字符，检测画布是否生成黑色墨迹
只有可以正常绘制文字的内嵌字体，才会被选用为替换文字的字体。

### 4.4 定位待替换文字
1. 使用PDF原生搜索功能匹配所有旧字符串所在的矩形区域；
2. 通过重叠面积比对，找到该坐标对应的原始文字片段，继承原有字号、字体、颜色、文字基线坐标；
3. 无法读取文字片段时自动启用参数兜底。

### 4.5 无痕覆盖文字
1. 使用白色遮盖注释，涂抹清除原有旧文字；
2. 在原始文字基线坐标写入新文本；
3. 优先加载原有兼容内嵌字体；字体缺失时自动兜底：英文调用helv字体、中文调用china‑s内置中文字体。

### 4.6 文件保存、临时资源清理
1. 使用临时文件原地覆盖原PDF，压缩存储；
2. 删除全部导出的临时字体文件，释放磁盘空间；
3. 统计当前PDF成功替换点位数量。

### 4.7 批量任务调度
循环处理全部PDF，区分三种运行状态：完成替换、文件跳过、文档处理异常报错；最后输出全局总替换次数。

## 5、文件夹目录规范
```
工作根目录
├─ pdf_text_replace.py（本脚本）
├─ 案件文件夹01
│   └─ 强制执行申请书.pdf
└─ 案件文件夹02
    └─ 材料.pdf
```
1. 脚本放置在根目录；
2. 程序递归扫描**所有层级子目录**内的PDF，不受文件夹嵌套深度限制。

## 6、分步操作指南
1. 使用记事本打开py脚本，修改顶部`REPLACEMENTS`配置项，填写旧内容、需要更新的新内容；
2. 终端切换至脚本所在目录，执行脚本；
3. 程序自动扫描全部PDF文档；
4. 查看控制台日志，查看每个PDF的处理状态：完成替换 / 无匹配文字跳过 / 文件报错；
5. 程序运行结束，输出全部文档一共修改的文字点位总数。

## 7、工具独有功能亮点
1. **深层目录遍历**：不限层级读取子文件夹PDF，适配分文件夹存放的各个案件卷宗；
2. **智能字体检测**：规避子集字体缺少汉字轮廓、替换文字变成空白方框的通病；
3. 样式完整复刻：新文字沿用原先字号、字体、文字颜色、文字位置，不会出现排版错位；
4. 兜底内置字体：找不到适配内嵌字体自动切换系统字体；
5. 白色蒙版覆盖旧文字，修改痕迹隐蔽；
6. 单个PDF报错不会中断批量任务；
7. 自动清理临时字体缓存文件，不会产生垃圾文件。

## 8、重要注意事项
1. **脚本会原地覆盖修改原PDF文件**，操作之前建议卷宗PDF提前备份；
2. 仅支持**可复制的文本型PDF**；图片扫描版PDF无法检索文字，会直接跳过；
3. 文字搜索严格匹配字符，空格、全角符号、换行字符不一致将无法命中；
4. Windows、Linux、MacOS均可运行，字体临时文件会存放至系统临时目录；
5. 多次运行脚本时记得更新REPLACEMENTS列表，防止重复替换。

## 9、故障排查清单
|故障现象|解决方案|
| ---- | ---- |
|替换之后中文显示方框空白|脚本字体检测机制失效；PDF内嵌字体缺少字形，程序自动切换内置china‑s中文字体依旧失效，可以提前更换PDF文档的字体|
|找不到PDF文件|确认脚本所在目录，程序只会扫描脚本所在文件夹以及它的子文件夹|
|文字替换之后位置偏移|PDF文字块结构复杂；程序依靠文字矩形匹配坐标，可尽量保证原文字span读取正常|
|处理PDF抛出异常|该PDF为加密、受限制、损坏的卷宗文件，需要先解除PDF权限限制|

## 10、工作流搭配方案
该工具可与你现有的两套案件处理脚本串联工作
1. PDF拆分脚本拆分整套执行卷宗；
2. 本批量替换脚本一键更新PDF里面当事人姓名、联系方式、身份证；
3. 被执行人信息提取脚本读取修改完成后的申请书，导出格式化txt文本。


# 提取申请书PDF中个人信息
## 1、程序概述
本Python脚本面向强制执行案件卷宗处理，自动遍历当前目录下全部一级案件子文件夹，读取文件夹内**强制执行申请书.pdf**；依靠正则表达式精准隔离被执行人文本区块，提取被执行人姓名、性别、联系电话、身份证号码、住址，自动规整执行请求文本错乱换行，最后生成排版对齐工整的`强制执行申请书.txt`摘要文档，实现案件基础信息一键批量采集。

## 2、运行环境
### 2.1 适配系统
Windows、Linux、macOS全平台可用
### 2.2 依赖安装
打开终端/CMD执行安装PDF文本解析库
```cmd
pip install pdfplumber
```
> pdfplumber：专门用于读取可复制文本版PDF，精准提取页面文字内容

## 3、目录结构规范
```
工作根目录
├─ info_extract.py（本提取脚本）
├─ (2026)执001号案件
│   └─ 强制执行申请书.pdf
└─ (2026)执002号案件
    └─ 强制执行申请书.pdf
```
1. 脚本存放至案件根目录；
2. **一级子文件夹名称即为案件案号**；
3. 每个案件文件夹内部必须存在 `强制执行申请书.pdf`；
4. 脚本仅扫描一级文件夹，不会读取深层嵌套的二级目录。

## 4、完整工作流程
### 4.1 遍历案件文件夹
读取工作目录下所有子文件夹，文件夹名称直接当作案件案号；
文件夹内不存在目标PDF文件则直接跳过当前案件。

### 4.2 PDF全文文本读取
调用pdfplumber加载PDF文档，循环读取每一页文字，拼接成完整申请书文本。

### 4.3 文本预处理
清除文本当中换行符、普通空格、全角空格，压缩为连续字符串，降低正则匹配干扰。

### 4.4 隔离被执行人专属文字区块（核心优化）
正则截取`被执行人：`起始，截止至「请求事项、事实与理由、1、」之前的文字片段。
> 解决申请书同时存在申请执行人、被执行人两套联系方式，防止错误抓取申请人信息。

### 4.5 正则提取全部被执行人字段
在隔离后的被执行人文本内依次匹配：
1. 姓名
2. 性别
3. 联系电话（兼容`电话：`、`联系电话：`两种写法）
4. 身份证号码（兼容大小写X）
5. 住址

任意字段匹配失败，默认赋值**未找到**。

### 4.6 提取并且修复执行请求内容
1. 抓取从`1、`开始，到事实与理由、此致之前的执行请求内容；
2. 智能处理PDF导出产生的无效换行：
    只要换行之后不是`数字+、`格式，就删除换行、拼接断开的文字，修复分段错乱。

### 4.7 格式化排版输出
1. `pad_key()`函数利用全角空格，统一所有标签（案号、姓名、住址等）至4个汉字宽度；
2. 分隔符` -> `可以全程垂直对齐；
3. 执行请求板块上方预留三行空白，版式清晰；

### 4.8 写入文本文件 & 异常容错
1. 在当前案件文件夹输出`强制执行申请书.txt`；
2. 单个PDF解析报错不会终止批量任务，控制台打印异常之后继续处理剩下卷宗。

## 5、分步操作指南
1. 将脚本放置在存放各个案件文件夹的根目录；
2. 确认每个一级案件子文件夹内含有强制执行申请书.pdf；
3. CMD进入根目录，运行python脚本；
4. 控制台输出正在处理的文件夹、txt生成成功提示；
5. 前往各个案件文件夹打开生成好的txt案件摘要。

## 6、工具核心特性
1. **被执行人区域隔离**，规避误提取申请执行人信息；
2. 自动修复PDF文本导出之后执行事项无故断行；
3. 全角空格对齐排版，txt文本字段分隔标识整齐；
4. 兼容两种联系电话前缀；身份证兼容末尾大小写X；
5. 异常隔离，单份PDF损坏不会打断批量处理；
6. 输出文件自动和源PDF放置于同一个案件文件夹。

## 7、注意事项
1. 仅支持**可复制文本PDF**；图片扫描版PDF无法读取文字，处理后所有字段均显示「未找到」；
2. PDF申请书文字格式改动过大时，需要调整脚本内部正则匹配语句；
3. 只会检索根目录的一级文件夹，深层嵌套文件夹不会扫描；
4. txt文件编码固定utf‑8，打开记事本出现乱码请使用记事本另存为更改编码。

## 8、故障排查
|故障现象|处理方案|
| ---- | ---- |
|全部字段均为未找到|PDF是扫描图片版，需要转换成可复制的文本PDF；或者申请书“被执行人：”文字格式存在改动|
|执行请求文字换行混乱|检查PDF原文排版，可微调换行正则表达式|
|读取PDF抛出报错|PDF文件损坏、加密受限，解除PDF权限之后重试|

## 9、整套案件处理流水线组合方案
三份脚本可以串联组成完整自动化工作流
1. **PDF拆分脚本**：拆分合并版卷宗材料，分离强制执行申请书、授权委托书、送达确认书；
2. **PDF批量文字替换脚本**：批量修改PDF内部当事人姓名、身份证、联系电话；
3. **被执行人信息提取脚本**：读取处理完毕的申请书，导出txt文字摘要，整理案件基础档案。


# 油猴-解除网站禁止密码自动填充
导入到浏览器的油猴插件中，可以让之前不能自动登录的网站变得可以自动登录。
